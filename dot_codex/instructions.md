## 🚦 Codex CLI Quickstart

Codex CLI is an agentic coding assistant. It enables natural language coding, file management, and code editing using patch-based workflows. **It automates tasks using patches rather than direct file edits.**

### ✨ Typical Session
1. Launch Codex CLI in your project directory.
2. Give natural language instructions (add feature/fix bug/code review).
3. Codex scans the codebase, applies or proposes patches, runs commands, and summarizes changes.

## ◀️ Allowed & Not Allowed

- **Allowed**: Modifying, testing, refactoring code and scripts in the local repo.
- **Allowed**: Reading/writing any file EXCEPT generated/locked files (requirements.txt, *.lock, etc—see below).
- **Not Allowed**: Directly editing autogenerated files (**always update the source format, recompile, then install!**).
- **Allowed**: Running linters/tests (pytest, black, ruff, etc).
- **Not Allowed**: Adding copyright/license headers unless instructed.

## 🔒 File Management Rules

- **Never edit these directly (always auto-generate!):**
    - `requirements.txt`, `requirements-dev.txt` — AUTO-GENERATED. Edit `.in` files and recompile with `uv pip compile`.
    - `storage/crewai/`, `storage/documents/`, `output/` — Internal storage and outputs.
- **Safe to edit:**
    - `requirements.in`, `requirements-dev.in`
    - All Python (`src/gapbot_crew/`), frontend, and config files
    - Documentation/markdown files

## 🧠 Codex Agent Workflow

### Code Editing & Patch Policy
- Always use the CLI's patch tool for all changes (no manual `vi`, `nano`, etc).
- For dependencies: 
    1. Edit the `.in` source file
    2. Run `uv pip compile requirements.in -o requirements.txt`
    3. Install with `uv pip install -r requirements.txt` (or `pip`)
- No code or file generation outside the workspace directory.
- Always lint (`ruff`, `black`) and test (`pytest`) before reporting changes as done.
- For large/complex edits, use atomic, stepwise patches per file/component.

### Command Summary
- `uv pip compile requirements.in -o requirements.txt`  — Recompile dependency lock file after `.in` changes
- `uv pip install -r requirements.txt`  — Install project deps for Codex or local agent
- `pytest` — Test suite
- `ruff check src/` — Lint
- `black --check src/` — Format checker

## 🧪 Testing & Validation
- Always run tests after any change that could affect code (unit, integration, or even doc fixes that could impact CLI output)
- If tests fail, diagnose root causes, document, and fix iteratively
- For dependency issues, always check importability (`python -c 'import package'`)

## 🛑 Troubleshooting (Codex CLI-specific)
- If you see `ModuleNotFoundError`, check requirements sync and pip install
- If a patch fails to apply, review the pre-/post-context or uniqueness of anchors
- If processes are killed (exit 143 or SIGTERM): check system resources, reduce test count, run targeted tests
- Always review the Codex summary before closing a session
- Document novel troubleshooting in this file for future Codex sessions

## 🎯 Best Practices
- Use atomic, focused patches — don't mix unrelated changes
- Update documentation alongside code when automated workflows or dependencies change
- Follow typing and code-style conventions detailed in CLAUDE.md and GEMINI.md
- Always provide step-by-step reasoning and summaries after multi-part patches or system changes

## 💡 Codex Agent Notes
- Codex CLI interprets all code tasks as patch-based, non-destructive edits
- Runs with restricted/no internet access (no pip install from PyPI during runtime unless wrapped in a shell command)
- Logs and summaries are auto-generated; review logs if anything unexpected happens
- Use ps/kill if the CLI is stuck or burning excess resources
